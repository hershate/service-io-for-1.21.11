# 编译指南

## 环境要求

| 项 | 要求 |
|---|---|
| JDK | **JDK 21**（本项目目标运行环境即 MC 1.21.11 所用的 Java 21）。不要用 JDK 25。 |
| Gradle | **9.7.0-rc-1**（与 `gradle/wrapper/gradle-wrapper.properties` 一致） |
| 操作系统 | Windows（本笔记命令基于 Git Bash；PowerShell/cmd 自行调整路径写法） |

本机 JDK 安装路径示例：`D:\Java\21`（即 `bin` 在 `D:\Java\21\bin`）。

> 关键原则：**全程 JDK 21**。`build.gradle.kts` 里 `toolchainJvm = 21`、`options.release.set(21)`，
> 产出的字节码是 Java 21（class major version 65），可在 JDK 21 / 1.21.11 运行。

## 获取 Gradle（国内必看）

项目自带的 `./gradlew` 会从 `services.gradle.org` 下载 Gradle，而该地址在国内会重定向到 **GitHub**，
经常连不上或极慢。改用国内镜像手动下载、直接运行 Gradle，**绕过 wrapper 的下载逻辑**。

```bash
# 1) 从腾讯云镜像下载 Gradle 发行版（官方源不可达时的替代）
mkdir -p /d/Tools/gradle
curl -L -o /d/Tools/gradle-9.7.0-rc-1-bin.zip \
  "https://mirrors.cloud.tencent.com/gradle/gradle-9.7.0-rc-1-bin.zip"
# 2) 解压
unzip -q /d/Tools/gradle-9.7.0-rc-1-bin.zip -d /d/Tools/gradle
# 3) 之后用这个 gradle 运行（路径按实际调整）
export GRADLE_HOME="/d/Tools/gradle/gradle-9.7.0-rc-1"
```

> 备选：编辑 `gradle/wrapper/gradle-wrapper.properties`，把 `distributionUrl` 改成上面的腾讯云镜像地址，
> 之后 `./gradlew ...` 即可。注意这是对受版本控制文件的改动。

## 完整编译命令

在项目根目录执行：

```bash
# 仅编译所有源码（最快，验证能否编译）
JAVA_HOME="/d/Java/21" "$GRADLE_HOME/bin/gradle" classes --no-daemon --console=plain

# 完整构建并打包（跳过测试，见下文说明），产出可发布的 jar
JAVA_HOME="/d/Java/21" "$GRADLE_HOME/bin/gradle" build -x test --no-daemon --console=plain
```

## 产物

| 路径 | 说明 |
|---|---|
| `plugin/build/libs/service-io-3.0.0-pre11-all.jar` | **shadow（fat）jar，即发布件**，放入服务器 `plugins/` |
| `build/libs/service-io-3.0.0-pre11.jar` | 核心 API（service-io）jar |
| `providers/*/build/libs/*.jar` | 各 provider 子模块 jar（通常不需单独使用） |

校验字节码版本（确认是 Java 21）：

```bash
unzip -p plugin/build/libs/service-io-3.0.0-pre11-all.jar \
  net/thenextlvl/service/plugin/ServiceBootstrapper.class | od -An -tx1 -N 8
# 期望开头: ca fe ba be 00 00 00 41   （0x41 = 65 = Java 21）
```

## 关于测试

构建命令带了 `-x test`。原因：本项目的"测试套件"（`plugin/.../commands/test/*TestSuite.java`）是
**游戏内命令式**的，需要在运行中的服务器里通过命令触发执行，并非可在构建期离线跑的 JUnit 单测。
因此离线构建时跳过测试；要真正验证功能，需把 jar 装进服务器在游戏内跑 `/service test`。
