# 国内网络与镜像

记录在本机（国内网络环境）构建时遇到的网络问题与解决办法。

## 结论速览

- **Gradle 发行版**：官方源（→GitHub）不可达/极慢 → 用**腾讯云镜像**。
- **Maven 依赖与 Gradle 插件**：项目声明的各仓库**都可达**，无需额外镜像。

## 1. Gradle 发行版：必须用镜像

`./gradlew` 默认从 `services.gradle.org/distributions/` 下载，该地址 **307 重定向到 GitHub**
（`github.com/gradle/gradle-distributions`）。在国内：

- `github.com`、`downloads.gradle-dn.com`：连接超时 / 极慢（实测 0–223 KB/s 且经常连接重置）。
- **腾讯云镜像可达且快**（实测 ~14 MB/s）：

```
https://mirrors.cloud.tencent.com/gradle/gradle-9.7.0-rc-1-bin.zip
```

解决办法见 [编译指南.md](编译指南.md) 的"获取 Gradle"。

> wrapper 自带 10 秒下载超时，且对"连接开了但 0 字节"这种死锁不会自动重试，
> 所以不要指望它在国内能自己下完——直接走镜像。

## 2. Maven 仓库：全部可达，无需镜像

实测以下仓库（项目 `build.gradle.kts` / 各 provider 声明的）均返回 200/301/404（即"可达"，
Maven 仓库根目录 404 是正常的）：

| 仓库 | 用途 | 状态 |
|---|---|---|
| `repo.papermc.io/repository/maven-public` | paper-api | ✅ |
| `repo.maven.apache.org/maven2`（中央仓） | 通用依赖 | ✅ |
| `repo.thenextlvl.net/releases` | `net.thenextlvl:*`（vault-api、i18n、version-checker 等） | ✅ |
| `repo.codemc.org/repository/maven-public` | bstats 等 | ✅ |
| `repo.extendedclip.com/.../placeholderapi` | PlaceholderAPI | ✅（301） |
| `repo.fancyinnovations.com/releases` | FancyHolograms / FancyNpcs | ✅ |
| `jitpack.io` | DecentHolograms（`com.github.*`） | ✅ |
| `plugins.gradle.org/m2` | Gradle 插件（shadow、plugin-yml 等） | ✅ |

所以**依赖与插件能正常下载**，只有 Gradle 发行版需要镜像。

## 3. JDK 25 不要下

本机构建只用 **JDK 21**（如 `D:\Java\21`）。曾考虑自动下载 JDK 25（Foojay/Adoptium），
但其下载链接最终都指向 GitHub（`github.com/adoptium/temurin25-binaries`）而不可达；
更重要的是本项目的目标就是 1.21.11 / JDK 21，**完全不需要 JDK 25**。
因此通过降级 Java 25 的 provider 依赖（见 [改动记录.md](改动记录.md)）来回避，而非下载 JDK 25。

## 4. 运行 Gradle 时的环境变量

```bash
# JDK 21
export JAVA_HOME="/d/Java/21"          # Windows 路径 D:\Java\21
# 解压后的 Gradle（从镜像下载）
export GRADLE_HOME="/d/Tools/gradle/gradle-9.7.0-rc-1"
```
